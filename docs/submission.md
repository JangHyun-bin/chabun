# 심사 시나리오와 제한

차분은 사고 직후 한 번에 하나의 주요 행동을 안내합니다. 기본 예시는 고속도로 2·3차로에서 발생한 우측 측면 충돌입니다. 아래는 구현 확인 순서입니다. 실행 환경과 검사 결과는 [검증 기록](verification.md)에 정리했습니다.

1. S1에서 충돌 정보의 출처와 부상 여부를 확인합니다. 에어백 전개는 차량 신호이며 부상은 사용자의 응답입니다. 알 수 없는 운전자 조작과 이동 경로는 미확인으로 남깁니다.
2. S2에서 119 칸의 10초 카운트다운을 확인합니다. 무응답 또는 명시적 연결 행동은 전화 화면을 열 뿐 통화·접수를 확정하지 않습니다. **괜찮아요**는 카운트다운을 취소합니다. 실제 발신 버튼은 누르지 않습니다.
3. S3에서 비상등·트렁크·대피를 순서대로 확인합니다. 확인 버튼은 사용자 응답이며 차량을 원격 제어하지 않습니다.
4. S4에서 접근 차량과 가드레일 밖 대피 지점 예시를 봅니다. 실제 주변 센서·지도·안전 경로 보장이 아닙니다.
5. S5에서 기록을 시작하고 직접 입력 또는 권한을 허용한 마이크 녹음을 저장합니다. 자동 전사는 없습니다. standalone에는 휴대폰 연결 화면이 없습니다.
6. S6에서 기록을 남긴 뒤 **경위서 초안 보기**를 누릅니다. 기록이 없으면 **예시 경위서 보기**로 열 수 있습니다. 예시 영상·사진·진술의 근거를 보고 문장을 수정·확인합니다. AI 사고 분석과 실제 블랙박스 수집은 없습니다.
7. S7에서 등록된 보험사가 수신처로, 바로 보낼 수 있는 기록·자료가 기본 선택으로 채워집니다. 범위를 고치고 미리본 뒤 승인합니다. **보험사에 전화하기**는 전화 화면만 열고 발신은 운전자가 합니다. 보험 접수번호와 처리 상태는 예시 결과이며 실제 기관 전송·접수가 아닙니다. 후속 차량 지원 안내도 실제 출동·예약을 요청하지 않습니다.

저장 성공 뒤에만 후속 절차를 엽니다. 저장 실패·충돌 때 입력을 보존하고 현재 상태에 머무릅니다. 중단·재개·거절·건너뛰기를 사용자의 승인이나 성공으로 대신하지 않습니다. 새 위험이 생기면 기록보다 안전 확인이 우선입니다.

## 별도 휴대폰 시연

서버와 연결 빌드가 있는 환경에서만 차량 QR을 읽고 양쪽 확인 숫자를 대조합니다. 차량에서 명시적으로 승인해야 연결됩니다. 휴대폰은 안전 확인 뒤 현장 전체·내 차·상대 차·번호판·바닥 흔적·신호등을 각각 저장하거나 명시적으로 건너뜁니다. 선택적 진술과 내용 확인 뒤 사본 범위를 고르고 승인합니다.

사본 준비는 보험사 전송이 아닙니다. 차량의 **사진 n/6**은 확보한 촬영 대상 수이며 파일 수가 아닙니다. 휴대폰 자료 상태가 차량에 보인다고 원본 본문까지 복사된 것은 아닙니다. 카메라가 없는 환경에서 생략한 항목은 촬영 완료로 세지 않습니다.

## 미검증과 미구현

실차와 운행 중 UX 제한, 화면의 물리 가독성, 안전 문구 승인, 개인정보 운영 정책과 사용자 이해도는 검증되지 않았습니다. 에어백 미전개 사고 자동 감지와 앱 종료 상태 자동 실행, 실제 Fleet·블랙박스·보험사·구호기관 연동은 없습니다. 신호를 읽지 못한 상태는 사고 없음의 증거가 아닙니다.

최종 영상의 제출 기준은 실제 native Pleos 화면 2560×1440, 30fps, 180초, 시작·끝 각 1초 페이드입니다. BGM 없이 안내 음성과 설명 음성의 겹침을 피합니다. 이 문서에는 미검증 다운로드 URL이나 임의의 해시·참가자·팀·동의·성과 수치를 넣지 않습니다.
